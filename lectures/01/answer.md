- 気づき・疑問：
  - 今回の2回ずつの測定では、flash-lite が平均1.31秒、flashが5.76秒、3.8-flashが126.67秒だった。3.8-flashはこの条件で最も時間がかかったが、2回の測定だけで一般的な性能を断定できない。ネットワークやサーバー状態、モデルの内部処理時間の影響もある。
  - 講座固有の質問には3モデルとも正しく答えられなかった。正しい3レベルは「基礎（同じ質問を繰り返して比較）」「実装（会話履歴を保持）」「発展（応答時間・トークン数を比較）」。出力トークンが多いほど応答時間が長くなるとは限らず、3.8-flashは3.5-flash-liteより出力トークンが少し多い程度でも、今回の応答はかなり長かった。
  - 最初の一括比較では、gemini-3.5-flashの2問目で503が返り、処理が中断した。その質問は1回だけ再実行して成功した。503はモデルの混雑を示すエラーで、レート制限超過を示す429とは別。記録した6件はすべて成功応答の計測値で、最初の503は所要時間・トークン数の表には含めていない。
  - Gemini APIの制限はプロジェクトやモデルにより異なり、RPM（リクエスト/分）・TPM（入力トークン/分）・RPD（リクエスト/日）などで管理される。短時間に呼び出しすぎると429になる可能性があるため、無料枠の現在値を [AI Studio のレート制限](https://aistudio.google.com/rate-limit) で確認する。今回は503を1回観測したが、429は発生しなかった。
  - 参考：[Gemini API レート制限](https://ai.google.dev/gemini-api/docs/rate-limits)
